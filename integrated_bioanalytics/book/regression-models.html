regression models

Does one measurement rise or fall with another, and by how much? Which of several predictors matters most, and does the response rise at the same rate in every group? What value should we expect for a sample whose response was never measured? Regression models answer both kinds of question, those about relationships and those about prediction. Both run through analytical chemistry, from the calibration curve that turns a detector signal into a concentration to studies asking which metabolites track a disease. This chapter fits straight-line models with one predictor and with several, reads what they say about the data, compares slopes between groups, uses a fitted line to predict values for new samples, and checks whether a model can be trusted. The machine learning models chapter builds on the same steps with more flexible models.

model use

A numerical model has two main uses: inferential and predictive.

  • Inferential uses aim to understand and quantify the relationships between variables, focusing on the significance, direction, and strength of these relationships to draw conclusions about the data. When using inferential models we care a lot about the exact inner workings of the model because those inner workings are how we understand relationships between variables.

  • Predictive uses are designed with the primary goal of forecasting future outcomes or behaviors based on historical data. When using predictive models we often care much less about the exact inner workings of the model and instead care about accuracy. In other words, it matters less how the model works as long as it is accurate.

The straight-line models in this chapter serve both purposes at once: their inner workings are simple enough to read directly, and they can also be used to predict. More flexible models, whose inner workings are harder to read and which are judged mainly on their predictive accuracy, are the subject of the machine learning chapter.

In this course, we will build models using a function called buildModel(). To use it, we give it our data and tell it which sets of values we want to relate. To do that, we need to specify (at least) two things:

  • predictors: the variables the model uses to make its prediction. They are the variables that go on the right of a formula and, in a plot, on the x axis (a second predictor is usually shown with color or facets). Depending on the model, these could be continuous or categorical variables.

  • response: the variable that the model should predict. It is the variable that goes on the left of a formula and on the y axis of a plot. Depending on the model, it could be a continuous value (regression) or a category/class (classification).

For model building, we also need to handle missing data. buildModel() stops if the data contain any missing values, so one way forward is to impute them, which means filling in each missing value with something. There are many ways to do this; here we use the median value of each column, with the impute() function from the Hmisc package:

any(is.na(metabolomics_data))
## [1] TRUE
metabolomics_data[] <- lapply(metabolomics_data, function(x) Hmisc::impute(x, median(x, na.rm = TRUE)))
any(is.na(metabolomics_data))
## [1] FALSE

single linear regression

We will start with some of the simplest models: linear models. There are a variety of ways to build linear models in R, but we will use buildModel(), as mentioned above. First, we will use least squares regression to model the relationship between predictor and response variables. Suppose we want to know if the abundances of iso-Leucine and Valine are related in our metabolomics dataset:

ggplot(metabolomics_data) +
  geom_point(aes(x = `iso-Leucine`, y = Valine))

Valine and iso-leucine abundance in patient blood samples. Scatter plot with iso-leucine abundance on the horizontal axis and valine abundance on the vertical axis; the points rise from left to right. Each point is one patient. Data: metabolomics_data.

It looks like there might be a relationship! Let’s build a linear regression model and use it inferentially to examine the details of that relationship:

basic_regression_model <- buildModel(
  data = metabolomics_data,
  model_type = "linear_regression",
  predictors = "iso-Leucine",
  response = "Valine"
)
names(basic_regression_model)
## [1] "model_type" "response"   "predictors" "model"     
## [5] "metrics"

The output of buildModel() holds the model_type, the names of the response and the predictors, the model itself, and the metrics describing the model and its performance. Let’s look at the model:

It shows us the r-squared, the total and residual sum of squares, the intercept (b in y = mx + b), and the coefficient for iso-Leucine (i.e. the slope, m), as well as some other things (we will talk about them in a second). Note that a variable whose name contains a space or a hyphen, like iso-Leucine, is listed in the variable column with backticks around it (`iso-Leucine`), so filtering on type is the more reliable way to find a coefficient. The slope here says that for every one-unit increase in iso-Leucine abundance, the model expects Valine abundance to rise by about 0.51.

Using a model to make predictions. A fitted model takes values of the predictor variable and returns the value of the response variable that the model expects for each one.

We can also use a function called predictWithModel() to make predictions using the model. We give it the data we want predictions for and the model. Here we predict a Valine abundance for every patient in the data set, from their iso-Leucine abundance:

  data = metabolomics_data,
  model = basic_regression_model
)

Now let’s talk about evaluating the quality of our model. For this we need some means of assessing how well our line fits our data. We will use residuals: the distance between each of our points and our line.

ggplot(predictions_from_basic_linear_model) +
  geom_point(aes(x = `iso-Leucine`, y = Valine)) +
  geom_line(aes(x = `iso-Leucine`, y = predicted_Valine)) +
  geom_segment(aes(x = `iso-Leucine`, y = Valine, xend = `iso-Leucine`, yend = predicted_Valine))

Residuals of the linear model of valine on iso-leucine. Scatter plot of measured valine against iso-leucine abundance with the model’s line; each vertical segment joins a measured value to the model’s prediction for it, so its length is that patient’s residual. Data: metabolomics_data.

We can calculate the sum of the squared residuals:

sum((predictions_from_basic_linear_model$Valine - predictions_from_basic_linear_model$predicted_Valine)^2)
## [1] 1.285459

Let’s call that the “residual sum of the squares”. It is the noise: the spread the model leaves unexplained. Does that mean our model is good? On its own, the number cannot tell us; it has to be compared to something. Let’s compare it to a super simple model that is just defined by the mean of the response in the data.

ggplot(metabolomics_data) +
  geom_point(aes(x = `iso-Leucine`, y = Valine)) +
  geom_hline(aes(yintercept = mean(Valine)))

A mean-only model of valine abundance. Scatter plot of valine against iso-leucine abundance with a horizontal line at the mean valine abundance, the prediction of a model that ignores iso-leucine. Each point is one patient. Data: metabolomics_data.

The flat line ignores iso-Leucine, so it misses the rise in Valine that the points show. How much better is our linear model than the flat line model? Let’s measure the distance between each point and the flat line:

ggplot(metabolomics_data) +
  geom_point(aes(x = `iso-Leucine`, y = Valine)) +
  geom_hline(aes(yintercept = mean(Valine))) +
  geom_segment(aes(x = `iso-Leucine`, y = Valine, xend = `iso-Leucine`, yend = mean(Valine)))

Residuals of the mean-only model of valine abundance. Scatter plot of valine against iso-leucine abundance with a horizontal line at the mean valine abundance; each vertical segment joins a measured value to the mean. Each point is one patient. Data: metabolomics_data. 


sum((metabolomics_data$Valine - mean(metabolomics_data$Valine))^2)
## [1] 2.154464

Let’s call that the “total sum of the squares”, and now we can compare it to our “residual sum of the squares”:

residual_sum_of_squares <- sum(
  (predictions_from_basic_linear_model$Valine - predictions_from_basic_linear_model$predicted_Valine)^2
)
total_sum_of_squares <- sum(
  (metabolomics_data$Valine - mean(metabolomics_data$Valine))^2
)
1 - (residual_sum_of_squares / total_sum_of_squares)
## [1] 0.403351

That is our R squared value. It is equal to 1 minus the ratio of the “residual sum of the squares” to the “total sum of the squares”. The R squared value can be thought of as:

  • The share of the variation in the response explained by the predictor, with the noise holding the rest (the analysis of variance chapter splits that share among several predictors).
  • How much better the line of best fit describes the data than the flat line.

Now, let’s put it all together and make it pretty:

predicting with a model

A fitted model is not tied to the data it was built from. It can predict the response for any table that has the same predictor columns, including samples whose response was never measured. That is the predictive use of a model, and it is often the reason for building one.

metabolomics_unknown holds measurements from seven new patients. It has every metabolite column that metabolomics_data has, so our iso-Leucine model can predict a Valine abundance for each of them. The table has no column identifying the patients, though, so first we number the rows. Because predictWithModel() returns the whole table with the prediction added to each row, every prediction stays attached to the patient it belongs to:

multiple linear regression

Now let’s try a multiple linear regression model. This is the same as a simple linear regression model, but with more than one predictor. (Other texts call the predictors independent or explanatory variables, and the response the dependent variable.) Simple linear regression uses one predictor to predict the value of the response, using a linear equation of the form y = mx + b. Multiple linear regression extends this concept to include two or more predictors, with a typical form of y = m1x1 + m2x2 + … + b. While simple linear regression describes a straight-line relationship between one predictor and the response, multiple linear regression fits a multi-dimensional plane in the variable space, providing a more nuanced picture of how the predictors together influence the response. It can give more accurate predictions, though it also requires more careful consideration of assumptions and of correlations among the predictors themselves. Let’s try it with the first 30 metabolites in our data set:

multiple_predictor_regression_model <- buildModel(
  data = metabolomics_data,
  model_type = "linear_regression",
  predictors = colnames(metabolomics_data)[3:32],
  response = "Valine"
)

which predictors matter most

Once a model has several predictors, a natural question is which of them drives the prediction. The metrics table reports a coefficient, a standard error and a p-value for every predictor:

  • Coefficient value: its magnitude and sign describe the expected change in the response when that predictor increases by one unit while all the other predictors are held constant.
  • p_value (or p_value_adj, adjusted for testing many predictors at once) is the p-value from testing whether that predictor’s coefficient is different from zero. Small p-values highlight predictors that are likely to matter after accounting for the rest.

It is tempting to rank the predictors by the size of their coefficients, but a coefficient is measured in the units of its own predictor, so raw coefficients cannot be compared with each other. Let’s see what goes wrong, with a model of Valine built from four metabolites:

four_predictor_model <- buildModel(
  data = metabolomics_data,
  model_type = "linear_regression",
  predictors = c("Phenylalanine", "2-Aminoadipate", "Tryptophan", "Propionate"),
  response = "Valine"
)

four_predictor_model$metrics %>%
  filter(type == "coefficient", variable != "(Intercept)") %>%
  arrange(desc(abs(value)))
##           variable      value    std_err        type
## 1    Phenylalanine 0.29172653 0.11152694 coefficient
## 2       Tryptophan 0.16871686 0.05478670 coefficient
## 3 `2-Aminoadipate` 0.15155542 0.03409275 coefficient
## 4       Propionate 0.05636311 0.03146305 coefficient
##        p_value  p_value_adj
## 1 1.047614e-02 0.0314284247
## 2 2.765831e-03 0.0110633260
## 3 2.548435e-05 0.0001274218
## 4 7.666589e-02 0.1533317727

Phenylalanine has by far the largest coefficient. But Phenylalanine barely varies from patient to patient: its standard deviation is about 0.12, against about 0.4 for 2-Aminoadipate and Propionate. A one-unit change in Phenylalanine is therefore an enormous change, far bigger than anything seen in the data, so its coefficient is large simply because its unit is large.

The fix is to put every predictor on the same footing before fitting, by scaling each one to a mean of zero and a standard deviation of one (scaling is introduced in the distances and scaling chapter). buildModel() does this when given scale_variance = TRUE, the same argument runMatrixAnalysis() uses. It scales the numeric predictors only, never the response, so each coefficient then means “the change in the response for a one-standard-deviation change in this predictor”, which can be compared across predictors:

scaled_four_predictor_model <- buildModel(
  data = metabolomics_data,
  model_type = "linear_regression",
  predictors = c("Phenylalanine", "2-Aminoadipate", "Tryptophan", "Propionate"),
  response = "Valine",
  scale_variance = TRUE
)

scaled_four_predictor_model$metrics %>%
  filter(type == "coefficient", variable != "(Intercept)") %>%
  arrange(desc(abs(value)))
##           variable      value    std_err        type
## 1 `2-Aminoadipate` 0.05963571 0.01341519 coefficient
## 2       Tryptophan 0.03906281 0.01268470 coefficient
## 3    Phenylalanine 0.03416658 0.01306187 coefficient
## 4       Propionate 0.02383590 0.01330569 coefficient
##        p_value  p_value_adj
## 1 2.548435e-05 0.0001019374
## 2 2.765831e-03 0.0082974945

After scaling, 2-Aminoadipate has the largest coefficient and Phenylalanine drops to third. The scaled ranking also agrees with the p-values, where 2-Aminoadipate has the smallest. Three further points:

  • The intercept is left out of the ranking with variable != "(Intercept)". It is not a measurement but the model’s baseline (after scaling it is simply the mean Valine abundance), so it does not belong in a list of predictors.
  • In a linear model, scaling changes the units of the coefficients, not the fit. Both models have the same r-squared, and they make the same predictions for new patients:

  • scale_variance is FALSE by default, so coefficients come back in the units the predictors were measured in, the form needed when a slope is itself the answer (the change in signal per unit of concentration on a calibration curve, for example). Turn it on to compare which predictor matters most, and leave it off to read coefficients in real units. Either model can make predictions: a model built with scale_variance = TRUE stores the mean and standard deviation of each predictor in the data it was built on, and predictWithModel() scales a new table with those same values, so the new table goes in as measured. (Scaling the columns by hand with mutate(across(c(...), scale)) before buildModel() gives the same coefficients, but that model then needs every new table scaled with the original data’s means and standard deviations, a step that is easy to get wrong.)

comparing slopes between groups

The predictors so far have all been numbers. A model can also take a categorical predictor, a column that names a group, and that opens up a common question: does the response rise with a predictor at the same rate in every group? Consider the elements of the periodic table. Density increases with atomic mass, but an element that is a gas at room temperature is about a thousand times less dense than a solid of similar mass, so one line through all of the elements would describe none of them well.

To give each group its own line, we describe the model with a formula instead of predictors and response. A formula puts the response on the left of a ~ and the predictors on the right, the same way as in the comparing groups chapter. Joining two predictors with * gives each group its own intercept and its own slope, while joining them with + would give each group its own intercept but force every group to share one slope (parallel lines). Elements whose density or state is not recorded are filtered out first, because buildModel() stops on missing values:

elements <- periodic_table %>%
  filter(!is.na(density_g_per_mL), !is.na(state_at_RT))

state_model <- buildModel(
  data = elements,
  model_type = "linear_regression",
  formula = density_g_per_mL ~ atomic_mass_rounded * state_at_RT
)

state_model$metrics %>% filter(variable == "r_squared")
##    variable     value std_err      type p_value p_value_adj
## 1 r_squared 0.6360092      NA statistic      NA          NA
predictWithModel(data = elements, model = state_model) %>%
  ggplot(aes(x = atomic_mass_rounded, color = state_at_RT)) +
    geom_point(aes(y = density_g_per_mL)) +
    geom_line(aes(y = predicted_density_g_per_mL)) +
    theme_bw()

Density rises with atomic mass for solids but barely at all for gases. Scatter plot with atomic mass on the horizontal axis and density in g/mL on the vertical axis; color shows each element’s state at room temperature (g, gas; l, liquid; s, solid), and each line is the fit for one state from a linear model with an atomic mass by state interaction. Each point is one element. Data: periodic_table.

Each state now has its own line. To ask which slopes differ from which, we pass the model to tukeyTest() and name the numeric predictor whose slope should be compared with slopes_of. The Tukey test compares the slopes of every pair of groups and corrects the p-values for the number of comparisons, much as the comparing groups chapter’s tests do for means. Piping the result into pGroups() gives each group a letter, as before, along with its slope (estimate) and that slope’s standard error:

state_model %>%
  tukeyTest(slopes_of = "atomic_mass_rounded") %>%
  pGroups()
##   treatment group spaced_group     estimate     std_err
## g         g     a           a  4.163966e-05 0.017065239
## l         l    ab           ab 8.599834e-02 0.043044343
## s         s     b            b 5.772680e-02 0.005833263

The letters read exactly as they do for means: groups that share a letter do not have significantly different slopes. Solids gain about 0.058 g/mL of density for every extra unit of atomic mass, while the slope for gases is indistinguishable from zero on this scale, and the two do not share a letter. The liquids share a letter with both. Only two elements (bromine and mercury) are liquid at room temperature, and two points pin down a slope very loosely, as the large standard error shows, so the test cannot tell their slope apart from either of the others.

assessing regression models

There are three aspects of a regression model that we should check on, to make sure the model isn’t violating any assumptions that we make when declaring the model to be valid:

  1. Residual-based assumptions. These checks are specifically about the behavior of residuals, which are the differences between observed values and model predictions. This group includes:

    • Linearity: examines if residuals show a random scatter around zero, indicating a linear relationship between the predictors and the response variable. Patterns or curves in this plot may indicate that the model does not adequately capture the true relationship, suggesting potential non-linearity.

    • Homoscedasticity (homogeneity of variance): looks at the spread of residuals to confirm that variance is consistent across fitted values. In other words, the spread of the residuals should be uniform regardless of the fitted values. To assess homoscedasticity, residuals are plotted against fitted values. A horizontal band of residuals indicates that the variance is consistent, supporting the homoscedasticity assumption. Conversely, patterns such as a funnel shape, where residuals spread out or contract as fitted values increase, suggest heteroscedasticity, indicating that the variance of errors changes with the level of the predictors.

    • Normality of residuals: assesses whether residuals follow a normal distribution, which matters for statistical inference in regression. To check this characteristic, a quantile-quantile (Q-Q) plot is used, where the residuals are plotted against a theoretical normal distribution. If the residuals are normally distributed, the points will align closely along a straight line. Significant deviations from this line indicate departures from normality, which may affect the reliability of statistical inferences drawn from the model.

  2. Predictor relationships. This check pertains to relationships among the predictor variables themselves, rather than their relationship with the response variable. In this case:

    • Collinearity: assesses multicollinearity, which occurs when predictors are highly correlated with each other. This can lead to inflated variances of regression coefficients, making it challenging to attribute effects to individual predictors. This check helps ensure that predictors are independent enough to provide clear, interpretable results for each variable’s influence on the response.

  3. Model fit and influence. These checks look at the overall fit of the model and assess if specific data points have undue influence on the model’s results. This group includes:

    • Posterior predictive check: this checks if model predictions align well with observed data, indicating a good overall fit. While not directly a residual analysis, it’s a comprehensive check for how well the model captures data patterns.

    • Influential observations: identifies data points that might disproportionately affect the model. High-leverage points can distort model estimates, so it’s important to verify that no single observation is overly influential.

We can assess all of these using:

multiple_regression_model <- buildModel(
  data = metabolomics_data,
  model_type = "linear_regression",
  predictors = colnames(metabolomics_data)[3:10],
  response = "Valine"
)

check_model(multiple_regression_model$model)

chapter summary

Download this summary as a one-page PDF

Building a regression model starts with what it is for. An inferential use reads the coefficients, their p-values and r-squared to describe how the response relates to the predictors; a predictive use applies the model to a table whose response was never measured. Four decisions follow. How many predictors: more can explain more of the variation, as r-squared shows. Whether to scale: build with scale_variance = TRUE before ranking coefficients by size, and leave it off to read them in real units. The fit and the predictions are the same either way. Whether slopes differ between groups: join the predictor and the group with *, not + (one shared slope), then compare the slopes with tukeyTest(slopes_of = ). Whether to trust it: check the residuals, the predictors and any influential points with check_model().
